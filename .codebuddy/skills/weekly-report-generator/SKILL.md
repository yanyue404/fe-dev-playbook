# Weekly Report Generator

## 触发关键词

当用户消息包含以下词语时，默认启用本技能：

- 周报
- 工作周报
- 本周总结
- 生成周报
- weekly report

## 输入来源

优先从用户提供的信息中提取内容，支持两种输入方式：

1. 直接粘贴日报内容（单日或多日）。
2. 提供日报文件路径，由代理读取后汇总。

可选补充信息：

- 周期范围（例如 `2026-04-06` 到 `2026-04-12`）
- 团队/项目名称
- 本周重点目标

## 汇总规则

1. 必须使用中文输出。
2. 仅基于用户提供的内容汇总，不臆造事实、数据、问题或成果。
3. 若用户未给明确周期，默认按"本周（周一到周日）"理解；若无法判断，先使用"本周"并在文末标注"统计范围待确认"。
4. 同类事项合并去重：将重复日报条目整合为一条，突出结果、进度变化和阻塞点。
5. 优先提炼"结果导向"信息：完成了什么、产生了什么价值、当前状态如何。
6. 风险项需包含影响与当前应对；若无风险，明确写"本周未识别出新增重大风险"。
7. 下周计划使用可执行表述，避免空泛描述。
8. 严禁捏造、推测日报中没有的信息，严禁自行编造截止日期、耗时统计、进度回落原因等。
9. 严格使用日报中的原话和给定的进度百分比，只做精简和归类，不做扩写和脑补。
10. **AI应用场景推断规则**：用户日报通常不会直接体现AI使用情况，需根据日报内容做合理化推测。推断依据如下：
    - 功能开发、页面实现、Bug修复 → 推断为「智能编码与视图生成」场景
    - 需求理解偏差、逻辑实现不精确 → 推断为「提示词指令与Skill能力调优」场景
    - 环境问题、兼容性修复、工具异常 → 推断为「问题排查与工具稳定性表现」场景
    - 代码优化、逻辑梳理、异常处理 → 推断为「代码质量检测与审核」场景
    - 文档编写、逻辑总结、方案输出 → 推断为「文档与知识输出」场景
    - 推断时必须结合日报实际工作内容，给出具体场景描述和总结评价，不能空泛
    - 若日报内容确实无法推断出任何AI场景，写"本周暂无AI应用场景"

## 同类项合并归纳（极重要）

在同一模块下，如果有多条同类型的修改，**必须归纳为一句话并加粗分类前缀**。绝对禁止一条一条平铺罗列！

**正确示范：**

```markdown
- **样式修复：**性别 radio 颜色、底部 logo 更换
- **功能开发：**新增社保校验逻辑、优化支付流程
```

**错误示范（严禁使用）：**

```markdown
- 修复了性别 radio 颜色问题
- 更换了底部 logo
- 新增社保校验逻辑
- 优化了支付流程
```

## 思考与总结

在核心模块下使用 `💡 思考与总结：` 标签，提炼经验与洞察：

- 仅在**核心模块**下使用，非核心模块不加
- 必须简短：**1-2 句话**
- 要上升到**机制、架构或后续优化策略**层面，严禁长篇大论

**正确示范：**

```markdown
- 💡 思考与总结：通过统一封装加密逻辑，后续新增渠道时只需关注业务差异，降低维护成本。
```

**错误示范（严禁使用）：**

```markdown
- 💡 思考与总结：这次开发让我学到了很多东西，包括如何更好地组织代码、如何与后端对接、如何处理各种边界情况等等，感觉收获很大。
```

## 输出模板（必须严格使用）

按以下 Markdown 标题输出，不改动章节顺序（共六个章节）：

```markdown
**一、 本周工作概述**

- <2~4 条，概述本周主要成果与整体进展>

**二、 重点工作进展详情**

**1. 模块名称（进度：XX%）**

- **分类归纳 1**：具体修复内容 1；具体修复内容 2。
- **分类归纳 2**：具体修复内容 1；具体修复内容 2。
- 💡 思考与总结：简短的架构/机制层面的总结。

**2. 模块名称（进度：XX%）**

- **分类归纳 1**：具体修复内容 1；具体修复内容 2。

**三、 主要问题与风险**

- <问题或风险 1：现象/影响/应对措施>
- <问题或风险 2：现象/影响/应对措施>
- <若无重大风险，写：本周未识别出新增重大风险。>

**四、 下周工作计划**

- <计划 1：具体动作 + 预期结果>
- <计划 2：具体动作 + 预期结果>
- <计划 3：具体动作 + 预期结果>

**五、 AI应用场景与产出**

<根据日报内容推断AI应用场景，按以下分类维度组织，每个场景包含：场景描述 + 总结评价>

**1. 智能编码与视图生成**
- **场景**：<从日报中涉及的功能开发、页面实现、Bug修复等工作中推断AI编码场景>。总结：<评价AI在编码/视图生成方面的效果与不足>
- 例：修复续保管理平台线上问题，能快速定位问题代码。总结：对于Bug问题修复非常好，基本不用手动coding
- 例：核保风控平台新增在线累计投保校验模型页面实现。总结：业务UI图片转视图能力快速生成页面代码，但产出代码需按照项目规范二次适配样式

**2. 提示词指令与Skill能力调优**
- **场景**：<从日报中涉及的需求理解偏差、逻辑实现不精确等工作中推断>。总结：<评价提示词约束的不足与优化方向>
- 例：在线累计保额是否均分责任保额需求，需要树状数据增加查询过滤，模糊查询，AI实现的是精确查询。总结：提示词需明确写明实现要求、约束条件及排除项
- 持续迭代打磨提示词，强化Skill输出管控，引导产出更贴合业务的高质量代码

**3. 问题排查与工具稳定性表现**
- **场景**：<从日报中涉及的环境问题、兼容性修复、工具异常等工作中推断>。总结：<评价工具稳定性表现>
- 例：优化智能营销平台项目，升级vuecliserver版本，带来一系列兼容问题。总结：高频调用Skill时易出现卡死、白屏异常

**4. 代码质量检测与审核**
- **场景**：<从日报中涉及的代码优化、逻辑梳理、异常处理等工作中推断AI辅助代码审查场景>

**5. 文档与知识输出**
- **场景**：<从日报中涉及的文档编写、逻辑总结、方案输出等工作中推断AI辅助文档生成场景>

<若本周日报内容无法推断出AI应用场景，写：本周暂无AI应用场景。>

**六、文档沉淀及输出**

- <本周新增或更新的文档/方案/复盘/操作手册等>
- <若暂无，写：本周暂无新增文档沉淀。>
```

**格式约束：**

- 会议沟通类精简罗列，不要用表格，不要加总时长
- 文档沉淀用简单列表展示，不要用表格
- 模块标题使用 `**数字. 模块名称（进度：XX%）**` 格式
- 列表项必须使用 `- **分类归纳：**内容` 格式，不得裸列

## 文件输入处理流程

当用户提供日报文件时，按以下流程执行：

1. 读取用户指定文件（可多文件）。
2. 提取每条日报的事项、进度、问题、输出物。
3. 按主题聚合并映射到六个章节。
4. 生成最终周报 Markdown 正文并直接返回给用户。
5. 仅在用户明确要求"保存文件"时再创建周报文件。

## 返回前检查

- 是否完全使用中文
- 是否严格使用六个章节标题
- 是否仅基于输入内容汇总
- 是否突出成果、风险与下周计划
- 是否为可直接复制的 Markdown
- 同类项是否已合并归纳（加粗前缀 + 分号分隔）
- 核心模块是否添加了 💡 思考与总结
- 格式是否符合模板（加粗标题、列表符、无表格）
