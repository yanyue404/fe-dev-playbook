# examples

以下示例用于约束输出风格：先“发现的问题”，后“开放问题/变更概览/剩余风险”。

## 示例 1：发现高优先级问题

**输入（用户请求）**
```text
请 review 这个支付回调改动，看看能不能上线。
```

**期望输出（示例）**
```markdown
## 发现的问题

### [Critical] 回调验签失败时仍更新订单为成功
- File: `service/pay/callback.ts`
- Issue: 验签失败分支没有中断流程，后续仍执行成功状态写入，可能造成伪造回调入账。
- Evidence: `if (!verifySign(payload)) { logger.warn(...) }` 后未 `return`，继续调用 `markOrderPaid(orderId)`。
- Fix: 验签失败立即返回并记录安全日志；仅在验签通过后进入状态更新分支。
- Test: 新增“验签失败不更新订单状态”的单测，并覆盖重复回调场景。

## 开放问题 / 假设
- 假设上游网关存在重试回调，需确认幂等键是否稳定。

## 变更概览
- 新增支付回调处理逻辑。
- 增加订单状态更新调用。

## 剩余风险
- 未看到压测/并发测试，重复回调下可能仍有竞态。
```

## 示例 2：中等级别 + 测试缺口

**输入（用户请求）**
```text
帮我做 PR review，重点看这个日期处理。
```

**期望输出（示例）**
```markdown
## 发现的问题

### [Major] 时区转换导致月底日期回退一天
- File: `utils/date/format.ts`
- Issue: 直接对本地时间做 `toISOString()` 再截断日期，UTC 偏移会导致部分时区出现日期回退。
- Evidence: `new Date('2026-03-01 00:30:00').toISOString().slice(0,10)` 在 UTC+8 可能得到前一天日期。
- Fix: 使用业务时区格式化（如 dayjs timezone）并明确输入输出时区。
- Test: 增加跨时区参数化测试，覆盖月初/月末边界。

## 开放问题 / 假设
- 无

## 变更概览
- 重构了日期格式化工具函数。
- 页面展示改为复用统一格式化入口。

## 剩余风险
- 仅看到 happy path，缺少 DST 切换日测试。
```

## 示例 4：多问题排序（高到低）

**输入（用户请求）**
```text
请按严重程度 review 这次库存模块改动。
```

**期望输出（示例）**
```markdown
## 发现的问题

### [Critical] 库存扣减与订单创建非原子，失败可导致超卖
- File: `service/inventory/reserve.ts`
- Issue: 先扣库存再创建订单，订单创建失败时未补偿回滚，可能累计错误库存。
- Evidence: `decreaseStock()` 与 `createOrder()` 不在事务内，也无补偿队列。
- Fix: 使用数据库事务或可靠消息最终一致性方案。
- Test: 增加“订单创建失败触发库存回滚”的集成测试。

### [Major] 重试机制缺少退避策略，可能放大瞬时故障
- File: `service/inventory/retry.ts`
- Issue: 固定间隔重试会在高峰期放大流量抖动。
- Evidence: 重试间隔恒定 `200ms`，无指数退避与抖动。
- Fix: 引入指数退避 + jitter，并设置最大重试时长。
- Test: 补充重试策略单测，验证退避曲线。

### [Minor] 错误日志缺少业务主键，定位成本高
- File: `service/inventory/reserve.ts`
- Issue: 日志未包含 `skuId/orderId`，线上排障困难。
- Evidence: `logger.error('reserve failed', err)` 未附带上下文字段。
- Fix: 增加结构化字段输出。
- Test: 补充日志字段快照测试或约定校验。

## 开放问题 / 假设
- 假设当前数据库支持所需事务隔离级别。

## 变更概览
- 新增库存预占与失败重试逻辑。
- 调整下单流程中的库存调用顺序。

## 剩余风险
- 若跨服务事务无法落地，需尽快补充补偿机制设计与演练。
```
